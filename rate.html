送出的評分會被當成事件丟進 Kafka，由 Spark Streaming 即時處理。送完後切到「模型監控儀表板」，就看得到這筆評分如何影響 MAE / PSI


舊使用者 (1–610，MovieLens 訓練集裡的 ID)：NCF 有這個 user 的 embedding，評分會立刻被拿去跟模型預測比對，會更新監控儀表板的 MAE / RMSE
新使用者 (例如預設的 999，不在訓練集)：評分照常送進 Kafka 並寫進 HBase，但 NCF 沒有這個 user 的 embedding，不會產生預測誤差，所以這筆不會動到 MAE / RMSE，只會影響 PSI（評分分布漂移）；要等下次重訓把這個 user 收進訓練集後才會被算進模型指標

幕後資料流

  1. Flask 把評分丟進 Kafka topic: user-ratings
  2. Spark Streaming 撈出來後，同時做三件事：
    • 更新「模型監控儀表板」（重算 MAE / RMSE / PSI）
    • 寫進 HBase user_ratings 表（給未來模型重訓）
    • 追加到 HDFS Parquet（讓 Trino 做 SQL 分析）
送完後切到「模型監控儀表板」就能看到 MAE / PSI 數字隨評分動
